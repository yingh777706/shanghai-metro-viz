# 分工2 · 数据需求单（提给分工1）

> 用途：补齐分工2「客流时空特征统计分析」结论中暂缺的三项时空指标（见《统计分析结论.md》「待补充」一节）。
> 分工1 同学产出后请放入 `data/`，或告知一个 `common.find_data()` 能定位到的目录，并同步更新本表状态。

## 1. 平均出行时长

- **用途**：统计全网加权平均出行时长，与平均出行距离（16.06 km）配合，估算全网平均出行速度 / 通勤半径。
- **需要字段**：每次出行（OD 对）的起点进站时刻与终点出站时刻，或直接给出单次出行耗时（分钟）。
- **建议格式**：优先在 `std_10min_od.csv` 追加 `duration_min` 列；若改大表成本高，可另出 `od_travel_time.csv`，列为 `originStation, destinationStation, avg_duration_min`（按 OD 对聚合的平均耗时）。
- **口径**：耗时 = 出站时刻 − 进站时刻（分钟）；剔除 <0 或 >180 分钟的异常值后再聚合。

## 2. 站点 → 线路映射

- **用途**：统计各线路的客流强度（线路总进站量 / 日均进站量），识别全网最繁忙线路。
- **需要字段**：`stationID` 与其所属线路（换乘站一行一条，可多行）。
- **建议格式**：`station_line.csv`，列为 `stationID, lineID`（或 `lineName`）。
- **口径**：换乘站需列出其全部经过线路；线路命名与报告一致（如 `Line 1` / `1号线`）。

## 3. 核心城区 vs 郊区分类

- **用途**：对比城区/郊区站点的客流规模与时间模式差异，验证「中心城区通勤主导、郊区低频」假设。
- **需要字段**：`stationID` 与其空间属性（核心城区 / 近郊 / 远郊，或按行政区 / 环线位置）。
- **建议格式**：`station_area.csv`，列为 `stationID, area_type`（取值如 `核心城区` / `郊区` 二分类，或更细三分类）。
- **口径**：给出分类依据（如以内环/外环为界，或按行政区），便于报告说明。
