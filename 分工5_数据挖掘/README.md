## 3. K-Means 站点聚类

### 3.1 运行方式

```bash
# 在项目根目录执行
python code/分工5/kmeans_station_clustering.py      # 约 1~3 分钟
```

### 3.2 方法与关键设计

1. **特征提取**：读取 `std_10min_inout.csv`（378 万行，分块读取防内存溢出），
   汇总为「站点 × 日期 × 小时」粒度，再对每个站点构造 69 维特征：
   - 工作日平均分时进/出站客流（17 小时 × 2 = 34 维）
   - 周末平均分时进/出站客流（34 维）
   - 日均总客流（1 维）
2. **log1p 压缩**：枢纽站与郊区站客流相差百倍以上，直接聚类会只按"流量大小"分组；
   先做 `log(1+x)` 再标准化，使时间**模式**与流量**规模**共同参与距离计算。
3. **选 K**：对 K=3~8 分别计算 SSE（肘部法则）与轮廓系数，
   综合分工要求的 5 类站点类型，最终取 **K=5**。
4. **簇类型判定**：聚类给出的是抽象簇号 0~4，代码用业务指标自动翻译成中文类型：
   - 日均总客流最大 → **综合枢纽站**；最小 → **郊区低频站点**
   - 早高峰(7-9时)进站占比最高 → **通勤居住站**（居民早上进站上班）
   - 早高峰出站 + 晚高峰进站占比最高 → **就业办公站**（通勤者早上到达、晚上返回）
   - 其余 → **休闲商圈站**（周末客流比例相对高的站点）

### 3.3 聚类结果

| 站点类型 | 站点数 | 平均日均总客流（人次） | 典型站点 |
| --- | --- | --- | --- |

| 就业办公站 | 75 | 约 9.9 万 | Jinke Road（金科路）、Xujiahui（徐家汇） |
| 通勤居住站 | 98 | 约 5.6 万 | Luheng Road、Fujin Road（外环居住区站点） |

- 最终 **K=5** 时 SSE = 4028.1，**轮廓系数 = 0.3070**；
  K=3 时轮廓系数最高（0.3734），但结合任务对 5 类站点的要求与 K>5 后 SSE 下降趋缓（肘部），
  选择 K=5 作为最终聚类数（选 K 详见 `分工5_数据挖掘/聚类/表1_K值评估指标.csv` 与图1）。
- 图3 分时客流画像验证了聚类有效性：通勤居住站呈"早进晚出"双峰，

## 4. ARIMA 短时客流预测

### 4.1 运行方式

```bash
# 在项目根目录执行
python code/分工5/arima_station_forecast.py     # 约 5~15 分钟（时间序列网格搜索较慢）
```

### 4.2 方法与关键设计

1. **典型站点选取**：从聚类结果中各选一个代表站——
   People's Square（人民广场，综合枢纽站）、Xinzhuang（莘庄，通勤居住站）。
2. **序列构建**：10 分钟数据汇总为小时级进站客流；夜间停运时段（23:00~次日6:00）
   客流恒为 0，不参与建模，序列按"每天 6:00~22:00 共 **17** 个小时"首尾相接，
   因此日内周期长度 s=17。
3. **平稳性检验**：ADF 单位根检验分别作用于原序列与一阶差分序列，
   p<0.05 视为平稳，据此确定差分阶数 d。
4. **模型定阶**：
   - 普通 ARIMA：网格搜索 p,q ∈ {0,1,2,3}，AIC 最小者胜出；
   - 季节 SARIMA：两阶段定阶——先固定周期项 (P,D,Q)=(1,1,1) 搜 p,q∈{0,1,2}，
     再比较其余 3 种周期项组合。周期项用于刻画日内"早晚高峰"节律。
5. **样本外检验**：预留最后 7 天（119 个运营小时）做测试集，
   同时与"上周同时刻"朴素基线对比，计算 **MAE、MSE、RMSE、MAPE**。

### 4.3 结果解读要点

- 实际误差数字见 `分工5_数据挖掘/预测/表6_预测误差指标.csv`（运行后生成），
  预测对比曲线见图4。
- **主要结论**：季节 SARIMA 的 MAE 约为普通 ARIMA 的一半
  （人民广场 1204 vs 2185 人次/小时；莘庄 868 vs 2027）——
  周期项对刻画地铁日内早晚高峰至关重要；普通 ARIMA 多步预测后
  迅速回归均值，完全无法跟随峰形。
- SARIMA 的预测曲线峰形与相位基本同步，但受线性均值回归影响
  峰值估计偏低，且 s=17 仅刻画日内周期、未区分工作日/周末，
  周末会出现虚高的通勤峰预测。
- 「上周同时刻」朴素基线误差最低（人民广场 MAE 662），
  说明地铁周级客流规律极强；但基线只是历史值的平移，
  无法适应节假日、天气突变等场景。改进方向：SARIMAX 引入
  天气等外生变量、工作日/周末分别建模、缩短预测步长做滚动预测。

### 3.5 方法对比与 K 值论证

```bash
# 在项目根目录执行（需数据就位，约 5~10 分钟）
python code/分工5/cluster_method_comparison.py
```

在同一份 69 维特征矩阵上，用 GMM 高斯混合与 Ward 层次聚类交叉验证 K-Means 的
选 K 与选型合理性，回应「为什么不是 K=3」「为什么用 K-Means」两类质疑：

- 输出（运行后生成于 `聚类/`）：`表7_聚类方法对比.csv`、`图5_聚类方法对比.png`、
  `聚类方法对比结论.md`（含基于真实数字的论证段落，可直接引用进报告）。
- 文字取舍（现有结论）：K=3 时轮廓系数最高（0.3734）高于 K=5（0.3070），但不同方法、
  不同指标的「统计最优 K」并不唯一；5 类站点类型（枢纽/办公/居住/商圈/低频）是任务设定
  的业务口径，K=5 与之对应且各方法在 K=5 的得分与峰值差距有限——属业务约束下的合理选择。

## 5. 代码可复现性说明

- 所有随机过程固定 `random_state=42`（KMeans、PCA）；
- 时间序列模型按 AIC 网格确定性搜索，重复运行结果一致；
- 两个脚本均分块读取大文件（每块 50 万行），8GB 内存电脑可运行；
- 运行顺序无依赖：聚类与预测脚本可独立运行；
  若想换预测站点，修改 `arima_station_forecast.py` 顶部 `TARGETS` 字典
  （键为 stationID，值站点名可在 `station_info.csv` 中查询，用 `common.find_data()` 定位）。
